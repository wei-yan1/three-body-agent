# StoryRole：女娲角色运行时计划

## 目标

把女娲产出的角色 Skill 从“检索到的角色资料”升级为“可运行的角色认知操作系统”。扣子只作为 Agent 能力参考，WeKnora 只作为解析、任务和可观测性设计参考；角色时期、角色状态和最终表达由 StoryRole 自己掌握。

## 已落地

- 文本导入具备编码识别、章节/卷/部解析、标题上下文、递归切分、保护区间、偏移和行号元数据。
- 导入任务具备文件级指纹、阶段状态、取消、重试、部分产物、解析统计、质量评分和章节连续性警告。
- 解析中间模型包含 `ParsedSection`、`ParsedParagraph`，可区分 narrative/dialogue，并保留说话人候选。
- 女娲运行时把 Skill 映射为：世界观镜片、决策启发式、表达 DNA、反模式、诚实边界、情绪底色和关系状态。
- Middleware 在模型调用前注入女娲运行时，不再只拼接“背景+语气+用户问题”。

## 运行时链路

```text
用户选择角色和时期
  ↓
加载该时期 stage record
  ↓
NuwaRoleSnapshot
  ↓
角色认知准备：理解需求 → 价值观评价 → 选择回应动作
  ↓
记忆、关系、人物 Skill、小说证据检索
  ↓
模型用角色表达 DNA 输出
  ↓
保存对话记忆和关系变化
```

## 女娲字段与运行时映射

| 女娲 Skill 内容 | 运行时作用 |
|---|---|
| 核心信念 / 阶段定位 | 角色看待问题的镜片 |
| 典型回答倾向 | 角色的决策启发式 |
| 语言风格 / 语气模拟 | 表达 DNA |
| 容易发生的人设漂移 / 反模式 | 负向约束 |
| 禁止知道的未来事件 / 诚实边界 | 知识边界与不确定性表达 |
| 情绪底色 / 当前人格状态 | 当前阶段初始状态 |
| 与其他角色的关系状态 | 对人评价和互动倾向 |
| 小说融合增强 / 原文证据 | 具体经历和可追溯依据 |

## 下一步

1. 增加角色时期列表接口，让前端/扣子可以读取女娲产出的所有时期。
2. 支持用户用时期名称或自然语言提示选择时期；没有明确选择时才使用默认时期。
3. 将“回应动作”结构化为内部状态：倾听、追问、安慰、反驳、提醒、承认不确定性、给建议。
4. 将对话中稳定形成的用户关系和角色状态写入长期记忆，而不是只保留原始聊天记录。
5. 建立阶段差异评测：同一问题在不同阶段必须体现不同的世界观、决策倾向和表达 DNA。

## 验收标准

- 同一个角色不同阶段回答同一个问题时，动机和回应动作不同，而不只是换语气。
- 角色遇到不确定问题时，会基于自己的诚实边界承认不知道，而不是自动百科化回答。
- 角色不会为了迎合用户放弃自己的价值观、偏见和反模式约束。
- 每个角色时期的运行时信息都能追溯到女娲 Skill 记录和小说证据。
